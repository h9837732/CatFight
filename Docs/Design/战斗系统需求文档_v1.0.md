## 1. 术语表

| 术语 | 英文 | 定义 |
|---|---|---|
| 生命值 | HP | 玩家/敌人的当前生命，归零即死亡 |
| 最大生命 | Max HP | 生命上限，决定血条格数 |
| 格挡 | Block | 抵消伤害的护甲，回合开始默认清零 |
| 能量 | Energy | 出牌资源，每回合重置为上限（草图称"体力条"） |
| 遗物 | Relic | 被动生效的永久增益，战斗中只读展示 |
| 道具 | Item / Potion | 战斗内可主动使用的消耗品，占用纵向道具栏 |
| 意图 | Intent | 敌人下一回合将执行的行为预告 |
| 卡牌区 | Card Zone | 抽牌堆 / 手牌 / 弃牌堆 / 消耗堆 |
| 状态 | Status | 力量、易伤、中毒等带层数的持续效果 |
| 特效体 | FX | 飘字、命中火花、震屏等纯表现对象 |

### 1.1 回合阶段（Phase）

```
BattleInit → PlayerTurnStart → PlayerAction ⇄ CardResolving
           → TurnEnding → EnemyTurn → (循环回 PlayerTurnStart)
           → BattleWin / BattleLose
任意阶段可进入 Paused
```

## 3. 战斗流程需求

### 3.1 战斗开始（BattleInit）

1. 淡入战斗背景，耗时 0.6s，玩家立绘与敌人从透明到不透明（0.4s）。
2. 初始化：`HP = MaxHP`、`Block = 0`、`Energy = EnergyMax`、所有状态清空。
3. 洗牌（Fisher–Yates，随机种子记录用于回放/调试），`抽牌堆 = 卡组`。
4. 结算遗物与道具的"战斗开始时"效果（如"战斗开始获得 1 点力量"）。
5. 顶部播放阶段提示条"战斗开始"（0.8s）后进入玩家回合。

**需求点**
- BR-3.1.1 洗牌必须使用可复现随机源（`RandomService`，种子存战斗快照）。
- BR-3.1.2 战斗开始效果按"遗物 → 道具 → 敌人"顺序结算，每个效果间隔 0.3s，不得跳帧合并。

### 3.2 玩家回合开始（PlayerTurnStart）

按顺序执行，每步有独立表现：

| 顺序 | 动作 | 说明 |
|---|---|---|
| 1 | 阶段提示"你的回合" | 1.0s，文字 + 轻微缩放 |
| 2 | 清空格挡 | 除非有"保留格挡"状态；伴随护盾破碎特效 0.25s |
| 3 | 能量重置为上限 | 已用块重新点亮，0.2s 逐格填充 |
| 4 | 回合开始状态结算 | 中毒扣血、再生回血、能力计数递减，逐个弹出飘字（间隔 0.2s） |
| 5 | 抽牌至 5 张 | 见 3.2.1；每张 0.12s 间隔，飞行动画 0.25s |
| 6 | 启用输入 | 手牌可交互、结束回合按钮点亮 |

**3.2.1 抽牌规则**
- 每回合抽 **3** 张（v1.2 从 5 下调，避免手牌每回合都堆到上限）。
- 手牌硬上限 **10**：抽到第 11 张时该牌直接进入弃牌堆并提示"手牌已满"（爆牌）。
- 抽牌堆为空时，将**弃牌堆洗回抽牌堆**（洗牌动画 0.4s）；两者皆空则不抽。
- 抽牌动画：从抽牌堆位置沿贝塞尔曲线飞入目标卡位，0.25s `ease-out`；目标位在此瞬间已按布局公式算好。

### 3.3 玩家行动（PlayerAction）

- 可通过**拖拽**或**点击卡牌 → 点击目标**两种方式出牌，二者等价。
- 点击卡牌时立即进行可用性判定（6.4），不可用时播放 0.15s 抖动 + 低沉提示音，不进入选中态。
- 拖拽出牌：卡牌跟随指针，抬升 40px 并放大 1.15 倍；进入合法目标区时目标高亮描边（2px，闪烁 0.6s 周期）。
- 松手位置在目标热区外 → 卡牌回弹（0.2s `ease-out-back`），不消耗任何资源。
- 按 `Esc` 取消选中/拖拽。
- 出牌成功 → 进入 `CardResolving`，此期间禁止新的出牌输入（见 3.3.1）。

**3.3.1 结算锁定**
- 结算期间输入队列最多缓存 1 次操作（防止连点丢手感），结算结束后立即执行。
- 群体伤害逐目标结算，每个目标间隔 0.15s。

### 3.4 回合结束（TurnEnding）

1. 玩家点击"结束回合"或按 `E` / `Space`（需二次确认开关，默认关闭）。
2. 手牌处理按 §6.6 策略执行（默认全部弃掉）。
3. 结算"回合结束时"状态（如再生回血、灼烧扣血）。
4. 阶段提示条"敌人行动"（0.8s），随后进入敌人回合。

### 3.5 敌人回合（EnemyTurn）

1. 按锚点索引 **从右到左**（索引 1 → n）依次行动，每个敌人：
   a. 意图气泡放大到 1.2 倍（0.15s）表示即将行动；
   b. 播放前摇动画（0.25s）；
   c. 结算效果（伤害/格挡/增益），伤害飘字 + 受击反馈（震屏 4px / 0.12s）；
   d. 间隔 0.4s 后轮到下一个。
2. 敌人死亡立即移出行动队列（不再行动）。
3. 全部行动完毕后 → 检查胜负 → 回到 3.2。

**需求点**
- BR-3.5.1 敌人回合内玩家所有输入禁用，结束回合按钮变灰（40% 透明度），但**暂停按钮可用**（暂停会把整个行动队列冻结在安全点）。
- BR-3.5.2 每个敌人行动前必须重算面板数值（不要用缓存的旧值）。
- BR-3.5.3 敌人行动总时长上限保护：若总时长 > 15s（例如 8 段攻击），自动压缩表现间隔至 0.2s。

### 3.6 胜负判定

| 结果 | 触发时机 | 表现 |
|---|---|---|
| 胜利 | 所有敌人 HP ≤ 0 | 0.8s 停帧 → 慢动作 0.5s → 敌人淡出 → 阶段提示"胜利" → 结算面板 |
| 失败 | 玩家 HP ≤ 0 | 0.8s 停帧 → 屏幕去色渐暗 1.0s → 阶段提示"失败" → 失败面板 |
| 同时归零 | 玩家与最后一名敌人同帧死亡 | **判定失败**（Roguelike 惯例，需在文档确认，见 §13） |

## 4. 界面布局规范

### 4.1 分辨率与适配

- 基准设计分辨率 **1920×1080**（16:9），UI 使用 `CanvasScaler = Scale With Screen Size`，`Match = 0.5`。
- 安全区：四周内缩 **48px**，所有信息不得进入安全区外。
- 支持比例：16:9 / 16:10 / 21:9 / 4:3；21:9 时背景横向延展，UI 保持居中；4:3 时允许上下留黑边。
- 最小可读分辨率 1280×720；UI 缩放系数下限 0.66。
- 目标平台：PC（键鼠 + 手柄）、移动端（触屏，见 §8.4）。

### 4.2 区域划分（基准 1920×1080，坐标系左上角为原点，y 向下）

**需求点**
- BR-4.3.1 所有坐标必须以 `ScriptableObject` / 配置文件外部化（`BattleLayoutConfig`），美术不得硬编码。
- BR-4.3.2 分区参数变动后需保证 1280×720 下不重叠（验收项，见 §12）。

### 4.4 遗物栏

- 横向排列，单格 72×72，图标居中 56×56，圆角 8px，边框 2px（稀有度颜色）。
- 悬停：放大 1.1，弹出 Tooltip（名称 + 描述，最大宽 320，自动换行）。
- 数量 > 3：第 4 格位置显示 `+N` 按钮（72×72），点击弹出 480×600 的滚动列表。
- 新增遗物：从 `+N` 位置飞入并缩放弹跳（0.35s，过冲 1.15），同时高亮描边脉冲 1.5s。
- 遗物只读：战斗中不可点击使用（被动生效）。

### 4.5 敌人区（锚点与排列）

**槽位定义（基准 1920×1080，锚点为脚底中心点）**

| 敌人数量 | 槽位 y | 槽位 x（索引 1 在最右） |
|---|---|---|
| 1 | 620 | [1240] |
| 2 | 620 | [1360, 1040] |
| 3 | 620 | [1560, 1240, 920] |
| 4+ | 620 | 水平间距 320，整体居中；超出屏幕时缩放到 0.9 |

- 排列规则：**索引 1 在最右侧**（草图"从右上角开始、从右往左"），后续索引依次向左。
- 不同数量切换时，位置变化用 0.25s `ease-out` 补间；**敌人死亡后的重排**同样适用（其余敌人保持相对顺序）。
- 敌人最大同时存在数 **3**（超过则分批入场，见 §13 待确认）。

**每个敌人子系统（自下而上）**

| 元素 | 尺寸/位置 | 说明 |
|---|---|---|
| 椭圆底座 | 200×28，脚底中心 y+4 | 半透明黑 25%，营造落脚感（草图的"椭圆"美化项） |
| 图下 HP 条 | 180×14，距底座上沿 8px | 深底 + 红色填充，**带数字 `34/50`（12px）居中** |
| 状态图标行 | 24×24，间距 4，HP 条下 6px | 最多 8 个，超出显示 `…` |
| 意图气泡 | 64×64，头顶上方 24px | 见 7.3 |
| 受击热区 | 220×260 | 比视觉略大，便于点选 |

**敌人 HP 条细节**
- 三层：底层（黑色 60%）→ 扣血预览层（深红 #8B1A1A，半透明）→ 当前值层（红 #D33）。宽度 180 固定，按比例填充。
- 受伤时：预览层从旧值位置向新值位置收缩（0.35s `ease-out`），当前值层同步，形成"血条掉血"观感。
- 血量归零：HP 条瞬间变空，敌人播放死亡动画（0.6s）后淡出，1.0s 后销毁。

### 4.6 玩家区

**立绘**
- 320×400，底部对齐；呼吸动画（缩放 1.0↔1.01，周期 3s），出牌时前倾 2px（0.1s）。
- 受击：闪红（0.1s × 2）+ 后仰 6px + 轻微震屏。

**玩家 HP 条（分段式，解决"长度不变"的矛盾）**
- 外框 520×24，圆角 12px，深色底（#1B1B1B，90%）。
- 分段：**格宽固定 26px**，格数 = `ceil(MaxHP / 10)`，格间 2px 间隙。
- 填充层：`filled = HP / MaxHP`，按比例跨格填充（支持半格），填充色 红 → 50% 以下变橙红并加入心跳脉动（0.8s 周期）。
- 格挡覆盖层：蓝色（#4A9CE8）从**右端**向左覆盖 `Block / MaxHP` 宽度，向上偏移 6px、高 28，带裂纹纹理。
- 受击预览层（ghost）：出牌/敌方结算前，用深红半透明条显示"本次将扣除量"，0.4s 后消散。
- 数值文本：`HP / MaxHP`（18px，描边 1px）居中；格挡徽章显示 `Block`。
- MaxHP 变化时：格数重排动画 0.3s + 整条高亮 3s（遗物/道具生效反馈，对应草图"血条会被遗物、道具影响"）。

**能量条（体力条）**
- 总宽 **300px 固定**，高 24；块数 `n = EnergyMax`；块宽 `w = (300 − 4×(n−1)) / n`，4px 间隙。
- 状态：可用 = 亮青蓝 + 内发光；已用 = 灰色 35% 透明度 + 无内发光。
- 当前值从**左至右**点亮（前 `Energy` 块亮，其余灰）。
- 临时能量（遗物/卡牌给予，回合结束消失）：用金色描边区分，显示在能量条右侧独立小球。
- 若 `EnergyMax > 6`（块宽 < 32）：退化为数字球样式（圆形 64×64 + 数字 24px）。
- 出牌时：对应块 0.15s 内逐个熄灭，伴随轻微缩放；能量不足时整条抖动 0.15s + 红色闪烁。

### 4.7 抽牌堆 / 弃牌堆 / 消耗堆

- 抽牌堆：卡背图标 96×128，右下角数字徽章显示张数；点击展开全部卡牌列表（只读，可排序）。
- 弃牌堆：同上，图标色或角标区分。
- 消耗堆：仅在本次战斗出现过消耗牌时显示，位置在弃牌堆右侧（可叠放在弃牌堆上，角标数区分）。
- 点击牌堆时暂停玩家输入（`PlayerAction` 挂起），列表打开期间不可出牌。

### 4.8 手牌区布局算法（v1.1 已实现）

**常量**：`cardW = 200`，`cardH = 280`，视觉可用横向跨度 `W = 1280`，最小可见宽度 `MIN_SLIVER = 64`，手牌上限 `H_MAX = 10`。

**排列公式**

```
n = 1:  x = 0（居中）
n ≥ 2:  fit   = (W − cardW) / (n − 1)
        step  = clamp(fit, MIN_SLIVER, cardW + gap)      // gap = 10
        total = cardW + step × (n − 1)
        x_i   = −total/2 + cardW/2 + i × step            (i = 0 … n−1)
        y_i   = arcH × (1 − (2p_i − 1)²)                  // 中间抬起，p_i = i/(n−1)，arcH = 22
```

- 宽度够就平铺，不够就平分；`MIN_SLIVER` 保证每张至少露出 64px（装得下左上角费用圆标）。
- **遮挡面积随张数自动变化**：`n=5` → `step=210`（不重叠）；`n=6` → `step≈208`；`n=7` → `step≈180`；`n=10` → `step=120`（每张露出 60%）。
- 层级：默认 `sibling = i`；**悬停卡或选中卡强制置顶**（`sibling = n−1`），因此叠压时鼠标指到的那张一定完整可见。

**悬停判定**

- 不用 `IPointerEnter`，改为每帧手动矩形判定：从最高图层往下扫，第一个命中者即悬停牌。
  原因：手牌每次刷新都会 Destroy/重建对象，事件式监听在鼠标不动时会丢失悬停态；按图层扫描天然与 `sibling` 顺序一致。
- 判定矩形额外放宽（左右 +10px、上下 +96px），避免卡片抬起/膨胀后鼠标“掉出”导致悬停闪断。

**悬停表现**

- 悬停卡：抬升 `74px`、缩放 `1.06`、置顶完整显示牌面（不再有被遮挡的可能）。
- 选中态：抬升 `56px`、缩放 `1.08`，并显示「再点一次打出 / 选择目标」提示条。
- 两者叠加时取较大值（悬停优先），由 `HandCardMotion` 每帧向目标值指数收敛（与帧率无关、无过冲）。

**卡牌可读性**

- 即使被遮挡，露出部分必须包含：**费用数字（左上角圆标）**、**卡图色块 / 类型图标**、卡名。

### 4.8.1 发牌动画

- **入牌框**：所有新抽到的牌从手牌区最右侧入口（`x = total/2 + cardW/2`，`y = −46`）滑入，逐张插入到前一张的左侧。
- **节奏**：单张滑动 `0.28s`（ease-out cubic），逐张间隔 `0.075s`；5 张牌约 `0.58s` 全部到位。
- **判定**：以卡牌实例引用做差集，只有“上一帧还不在手里”的牌才播入场动画；刷新界面不会让整排牌重新飞入。
- **重排**：已在手里的牌从上一帧的实际位置平滑滑到新槽位，出牌后不会瞬移。
- **刷新去重**：手牌视图按「牌列表 + 行动点 + 阶段」生成指纹，指纹未变则跳过重建，避免同一帧被多次刷新打断动画。

### 4.8.2 遗物 / 道具悬停说明

- 遗物格（左上横排）与消耗型道具格（其下方纵排）在鼠标悬停时弹出说明框：标题为 `遗物 · 名称` / `道具 · 名称`，正文为效果描述。
- 说明框贴在对应栏位右侧，宽度 `340px`（道具 `300px`），高度按文字长度自适应；同一时刻只存在一个，鼠标移出即消失。
- 说明框是纯展示层（`raycastTarget = false`），不拦截点击。

## 6. 战斗规则

### 6.1 能量

- `EnergyMax` 默认 **3**，`Energy` 每回合重置为 `EnergyMax`。
- 卡牌消耗 `cost` 点能量；`cost = -1` 表示 X 费（消耗全部当前能量，效果按消耗量计算）。
- 能量不足 → 卡牌不可用（见 6.4）。
- 临时能量：回合结束清零，不参与"重置"（重置为先清空再填 `EnergyMax`）。

### 6.2 格挡

- `Block` 用于吸收伤害，吸收量 = `min(Block, incomingDamage)`。
- 默认在**玩家回合开始时**清零（敌人格挡在其回合开始时清零）。
- 具有"保留格挡"状态时不清零。
- 格挡上限默认 **999**。

### 6.3 伤害结算顺序（严格按序）

```
1. base = 卡牌/意图基础值
2. += 力量（Strength）× times
3. ×= 攻方虚弱修正（0.75，向下取整）
4. ×= 受方易伤修正（1.5，向下取整）
5. += 遗物/道具的伤害修正（加法，逐个结算）
6. -= 受方格挡（Block = max(0, Block − dmg)；dmg = max(0, dmg − Block)）
7. HP = max(0, HP − dmg)
8. 触发"受到伤害后"状态（荆棘反弹、受伤回能等）
9. 检查死亡
```

**需求点**
- BR-6.3.1 每一步取整方式必须固定为"向下取整"，并写单元测试。
- BR-6.3.2 多段攻击（`times > 1`）每段独立走完整流程（力量加成每段都吃）。
- BR-6.3.3 所有修正必须可在调试面板中逐条打印（`BattleLog`）。

### 6.4 卡牌可用性判定

卡牌"不可用"当且仅当满足任一：

1. `Energy < cost`（且 `cost ≠ -1`）；
2. 目标非法（`SingleEnemy` 但场上无敌人）；
3. 有"缴械"等封锁类状态封锁该类型牌；
4. 当前处于 `CardResolving` / `EnemyTurn` 等非 `PlayerAction` 阶段；
5. 手牌已满时被抽到（不进入手牌）。

表现：灰度 55% + 费用圆标变红 + 悬停提示不可用原因（16px，浅灰）。

### 6.5 状态效果表

| 状态 | 类型 | 叠加 | 结算时机 | 效果 |
|---|---|---|---|---|
| 力量 Strength | Buff | 加法 | 伤害计算步骤 2 | 每层 +1 基础伤害 |
| 敏捷 Dexterity | Buff | 加法 | 获得格挡时 | 每层 +1 格挡 |
| 易伤 Vulnerable | Debuff | 层数 | 受击时 | 受到伤害 +50%，回合结束层数 −1 |
| 虚弱 Weak | Debuff | 层数 | 造成伤害时 | 造成伤害 −25%，回合结束层数 −1 |
| 脆弱 Frail | Debuff | 层数 | 获得格挡时 | 获得格挡 −25%，回合结束层数 −1 |
| 中毒 Poison | Debuff | 层数 | 回合开始 | 失去等于层数的 HP（无视格挡），层数 −1 |
| 再生 Regen | Buff | 层数 | 回合结束 | 回复等于层数的 HP，层数 −1 |
| 荆棘 Thorns | Buff | 层数 | 受击后 | 反弹等于层数的伤害给攻击者 |
| 缴械 Disarm | Debuff | 层数 | — | 无法打出攻击牌 |
| 保留格挡 Barricade | Buff | 不叠加 | 回合开始 | 格挡不清零 |

- 图标规格：48×48 原始，显示 24×24；层数角标 14px 白字黑描边。
- 悬浮 tooltip：名称 + 效果 + 剩余层数（最大宽 300）。
- 新增状态时同步更新 `StatusIconAtlas` 与本文档。

### 6.6 手牌结束策略

| 数值 | 值 | 含义 |
|---|---|---|
| `HandLimit` | 10 | 手牌**硬上限**（战斗中任意时刻，含抽牌效果） |
| `EndTurnHandLimit` | 5 | **回合结束时**允许保留的手牌数 |
| `DrawPerTurn` | 3 | 每回合抽牌数（v1.2 由 5 下调） |
| `handPolicy` | `KeepAll` | 手牌跨回合保留（`DiscardAll` 为备选：每回合弃光重抽） |

**两条规则分开看：**

- **战斗中**最多拿 10 张——抽牌类效果（卡牌、迅捷药水）可以把牌堆到 10 张。
- **结束回合时**只能带走 5 张——超出的部分必须由玩家自己选择弃掉，这就是 **弃牌环节**。

### 6.6.1 弃牌环节

点击「结束回合」时，若 `手牌数 > EndTurnHandLimit`，先弹出弃牌面板，弃完才进入敌人回合。

| 项 | 规则 |
|---|---|
| 触发条件 | `Hand.Count > EndTurnHandLimit`（即 6 张及以上） |
| 必须弃掉 | `Hand.Count − EndTurnHandLimit` 张（正好这么多，不能多不能少） |
| 选择方式 | 点击卡牌切换选中；选满后不再接受新选择，可再点取消 |
| 视觉反馈 | 选中牌加红色描边 + 中央「弃」角标 + 略微缩小（0.96） |
| 确认 | 选中数 = 应弃数时「弃牌（n/N）」按钮才可点 |
| 结果 | 选中的牌进入弃牌堆，未选中的保留到下回合 |
| 期间锁定 | 面板打开时 `_busy = true`，出牌 / 用道具 / 结束回合全部不可用 |
| 布局 | 卡牌网格，每行最多 5 张，10 张刚好两行；用网格而非叠压，因为玩家必须读清每张才能决定 |

**需求点**

- BR-6.6.1 弃牌面板不改变 `Phase`，仍在 `PlayerAction` 内（避免 `EndTurn` 被重复调用）。
- BR-6.6.2 未超限时**不弹面板**，直接进敌人回合，不打断节奏。
- BR-6.6.3 弃牌走 `BattleState.DiscardFromHand(List<int>)`，内部按**下标降序**删除，避免偏移。
- BR-6.6.4 顶栏常驻「手牌 n/10」，超限时追加「· 结束需弃 k」并变红。

### 6.6.2 回合开始抽牌（可配置）

`BattleState.drawFillToEndLimit` 决定 KeepAll 下每回合抽多少（`DrawPerTurn` 已降到 3）：

| 值 | 抽牌数 | 效果 | 适用 |
|---|---|---|---|
| `false`（**默认**） | `min(3, 10 − 手牌数)` | 每回合固定抽 3 张，封顶硬上限 10 | 正常玩法。3 张 ≈ 3 点能量能打出的张数，手牌自平衡在 0~5 |
| `true` | `min(3, 5 − 手牌数)` | 保留几张就补几张，回合开始时手牌 ≤ 5 | 想在「保留」上做文章时的备选 |

**示例（默认 `false`，正常出牌）**

| 回合 | 回合开始 | 抽牌 | 打出 | 回合结束 | 弃牌环节 |
|---|---|---|---|---|---|
| 1 | 0 | 3 | 3 | 0 | 无 |
| 2 | 0 | 3 | 3 | 0 | 无 |
| 3 | 0 | 3 | 2（强力一哈 2 费） | 1 | 无 |
| 4 | 1 | 3 | 3 | 1 | 无 |

手牌始终远低于 5，**弃牌环节基本不触发**。

**示例（一张牌都不出，故意囤牌）**

| 回合 | 回合开始 | 抽牌 | 回合结束 | 弃牌环节 |
|---|---|---|---|---|
| 1 | 0 | 3 | 3 | 无 |
| 2 | 3 | 3 | 6 | 需弃 1 张 |
| 3 | 5 | 3 | 8 | 需弃 3 张 |

即：只有玩家主动囤牌、或被抽牌类效果（战斗恍惚 / 迅捷药水）灌满时才会进入弃牌环节，这正是「大于 5 张才弃」的设计意图。

### 6.6.3 手牌结束策略枚举（保留兼容）

| 策略 | 字段值 | 行为 |
|---|---|---|
| A 保留累积 | `KeepAll` | 默认，配合弃牌环节 |
| B 弃光 | `DiscardAll` | 回合开始前全部入弃牌堆，每回合固定 5 张（弃牌环节不会触发） |

### 6.7 遗物与道具的效果时机

支持的钩子（`Hook`）：

| 钩子 | 时机 |
|---|---|
| `OnBattleStart` | 战斗开始 |
| `OnPlayerTurnStart` | 玩家回合开始（清格挡之后） |
| `OnCardPlayed` | 每张牌打出后 |
| `OnDamageDealt` / `OnDamageTaken` | 造成/受到伤害后 |
| `OnEnemyKilled` | 敌人死亡时 |
| `OnTurnEnd` | 回合结束 |
| `OnBattleEnd` | 战斗结束 |

- 遗物：被动，自动触发（无点击）。
- 道具：主动，点击使用（消耗一格），使用后从道具栏移除；同一时刻只能有 1 个道具在使用动画中。
- 道具使用方法：点击 → 若需目标则进入选择态 → 点击目标生效；`Esc` 取消且不消耗。

## 7. 敌人与意图

### 7.1 敌人行动模式

- `Loop`：按 `intentPattern` 循环。
- `Random`：按权重随机，禁止连续 3 次同一种"攻击"（防呆）。
- `Conditional`：带条件表达式（如"HP < 50% 时改为蓄力"），表达式由配置提供，禁止硬编码。

### 7.2 敌人回合内容类型

| 类型 | 图标 | 显示规则 |
|---|---|---|
| 攻击 | 剑 | 显示伤害数字；多段显示 `3×2` |
| 防御 | 盾 | 无数字，或显示格挡值 |
| 增益 | 上箭头 | 不显示具体数值（除非设计允许） |
| 减益 | 下箭头 | 同上 |
| 未知 | 问号 | 特定敌人/首回合 |
| 睡眠 | Zzz | 不行动，被攻击后唤醒 |

### 7.3 意图显示规范

- 位置：敌人头顶上方 24px，64×64 气泡（圆角 12，底色半透明黑 55%）。
- 攻击意图：剑图标 + 伤害数字（下方 20px 粗体，颜色：#FF6B6B）。**伤害数字必须是扣除当前状态后的最终值**（含力量/虚弱）。
- 多段：`数字 × 段数`，如 `3×2`，字号自动缩小到 16px。
- 意图在**玩家回合开始**时刷新，玩家回合内不可变（避免"边打边变"的挫败感）。
- 敌人回合中，当前行动的敌人意图气泡放大 1.2 倍并加亮边框。

## 10. 战斗结算面板

**胜利**
1. 面板淡入 0.4s，居中 900×620。
2. 内容：金币（+N，数字滚动 0.5s）、卡牌奖励（3 选 1，可跳过）、遗物奖励（若有）、"继续"按钮。

**需求点**
- BR-10.1 结算面板打开后战斗场景冻结（时间缩放 = 0），音乐切换为结算曲。

## 12. 性能与技术需求

| 指标 | 目标 |
|---|---|
| 帧率 | PC 60 FPS 稳定；移动端 30 FPS 下限 |
| 战斗场景 DrawCall | ≤ 120（UI + 精灵合批） |
| 首次进入战斗加载 | ≤ 1.5s（PC）/ ≤ 3s（移动端） |
| 内存占用 | ≤ 512MB |
| 卡牌实例池 | 手牌 + 牌堆共用对象池 30 个，禁止运行时 Instantiate/Destroy 频繁创建 |
| UI 刷新 | 数值变化采用脏标记，禁止每帧 SetText |

**工程约束**
- UI 使用 `Canvas`（Screen Space - Camera），静态元素与动态元素分 Canvas，减少重建。
- 卡牌图集 2048×2048，敌人图集 2048×2048，UI 图集 1024×1024。
- 所有布局参数来自 `BattleLayoutConfig`（ScriptableObject）。
- `BattleLog`（结构化日志）在开发版开启，正式版关闭；日志包含每次伤害的逐步计算。

## 附录 B：布局公式速查

```
血条格数     nGrid  = ceil(MaxHP / 10)
血条填充比例 fill   = HP / MaxHP
血条总宽     Wbar   = 520（固定，与 MaxHP 无关）
能量块宽     wBlock = (300 − 4 × (EnergyMax − 1)) / EnergyMax
手牌步长     step   = min(220, (1080 − 220) / (n − 1))
手牌总宽     total  = 220 + step × (n − 1)
第 i 张中心 x x_i    = 900 − total/2 + 110 + i × step
弧顶偏移     dy_i   = −28 × (1 − (2i/(n−1) − 1)²)
```
