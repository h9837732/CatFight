## 1. 草图原文与解读

### 1.1 草图标注原文

> 地图，初始为 1 个圆形，然后可能是连了 1 或 2 个圆形，每个球随机连接一个/多个，最多不超过 4 个每行。

### 1.2 解读

| 草图元素 | 含义 |
|---|---|
| 外框（波浪边矩形） | 地图承载在**一页纸 / 羊皮纸**上，是"实物地图"而不是 UI 面板 |
| 圆形节点 | 一个可进入的关卡点 |
| 节点间连线 | 可行进路径，单向（只能向上/向前） |
| 上窄 → 中宽 → 下窄的形态 | 分叉后**重新合流**，不是开放扇形的宽 DAG |
| "初始为 1 个圆形" | 单一入口，玩家从同一点出发 |
| "每行最多 4 个" | 行宽上限，限制同时在场的路径数 |

### 1.3 判定

| # | 草图规则 | 判定 | 处理 |
|---|---|---|---|
| 1 | 初始 1 个节点 | 保留 | 与《邪恶铭刻》一致，比尖塔的 6 入口更有"单线朝圣"感 |
| 2 | 首层连 1 或 2 个 | 保留 | 第一刀必须给出"选择感"，2 个是下限 |
| 3 | 每个球随机连 1 或多个 | **修改** | 改为"出度 1–2 的约束连边 + 反向修补"，纯随机会产生孤儿节点与死路 |
| 4 | 每行不超过 4 个 | 保留并补下限 | 1–4，且相邻行宽度变化限制为 ±1 |
| — | 未标注 | **新增** | 汇聚节点、禁止边交叉、节点类型配额、不可回溯、未选分支划掉、存档种子化 |

## 2. 设计目标与非目标

### 2.1 目标

1. **每次开局都不同**，但有明确的"节奏骨架"（张弛交替，不会出现连续 5 场普通战斗）
2. **不存在走不通的分支**：所有岔路都能汇回主线，玩家不会因为选错而卡死
3. **一屏可读**：整幕地图不需要长距离滚动，符合"一张纸"的观感
4. **手绘质感**：墨线干净、不交叉，节点有不规则的手绘感
5. **确定性可复现**：同一个种子必然生成同一张图，支持存档恢复与调试重放

### 2.2 非目标

- 不做地图上的自由移动（不是走格子 Roguelike）
- 不做回溯 / 传送
- 不做随机生成后的手动编辑（编辑器工具仅用于预览与调参）

## 3. 与其他游戏的定位差异

| 维度 | 杀戮尖塔 | 邪恶铭刻 | **CatFight（本方案）** |
|---|---|---|---|
| 拓扑 | 15 层 × 7 列宽 DAG | 蜿蜒单主线 + 分叉再合流 | 分层带状图，**每行 1–4，强制汇聚** |
| 入口 | 6 个起点 | 1 个 | **1 个** |
| 视口 | 纵向长滚动 | 一屏 + 相机平移 | **一屏可读，最多 1.5 屏** |
| 边交叉 | 允许（算法尽量避免） | 基本不存在 | **禁止（算法保证）** |
| 回溯 | 不可 | 不可，未选分支被墨迹划掉 | **不可，未选分支"用墨划掉"** |
| 观感 | UI 面板 | 桌面上的实物纸地图 | **纸页 + 手绘墨线 + 棋子** |
| 存档 | 记录完整地图 | — | **只记种子 + 已走路径** |

> 说明：表中"邪恶铭刻"一栏为对其观感与分支手感的归纳，用于确定本作方向；不代表其内部实现细节。

## 4. 拓扑规范

### 4.1 术语

| 术语 | 定义 |
|---|---|
| 行 Row | 地图的纵向层，从上到下编号 0…N-1 |
| 节点 Node | 行内的一个关卡点，`(row, index)` 唯一标识 |
| 汇聚点 Anchor | 强制只有一个节点的行，所有分支在此合流 |
| 出度 / 入度 | 指向下一行 / 来自上一行的边数 |
| 路径 Path | 从起点到 BOSS 的一条节点序列 |

### 4.2 结构参数

| 参数 | 值 | 说明 |
|---|---|---|
| 总行数 `rowCount` | **14**（不含 BOSS） | 一幕的游戏步数；建议 12–16 |
| BOSS 行 | 独立，1 个节点 | 第 `rowCount` 行 |
| 每行节点数 `counts[row]` | 1–4 | 由 `maxNodesPerRow` 配置 |
| 相邻行宽度变化 | ±1 | 禁止 1→4 这类突变 |
| 起始节点数 | 1 | 第 0 行 |
| 汇聚行 `convergeRows` | **[6, 12]** | 强制 `counts = 1` |
| 节点出度 | 1–2 | 保证每个节点至少有一个"下一站" |
| 节点入度 | ≥ 1 | 保证无孤儿节点 |
| 边方向 | 只向下（行号递增） | 无环 |

### 4.3 形态示意

```
row  0            ●              起点（1）
                 / \
row  1         ●     ●           2
               |\   /|
row  2         ● ● ● ●           4（最宽）
               | | | |
row  3         ● ● ● ●           4
               | | | |
row  4         ●  ●  ●           3
                \ | /
row  5           ●  ●            2
                  \/
row  6             ●              ★ 汇聚锚点（强制 1）
                 / | \
row  7         ●   ●   ●         3
               ...                （重复一轮）
row 12             ●              ★ 汇聚锚点
                   |
row 13             ●
                   |
        BOSS       ◆
```

### 4.4 为什么必须"汇聚"

| 不汇聚（尖塔式） | 汇聚（本方案） |
|---|---|
| 分支可能永远不再相交，后期无法回收 | 每 5–6 行强制收拢，节奏有"章节感" |
| 容易出现某条分支过早结束（死路） | 所有分支结构上必有出口 |
| 地图越到后期越宽，视觉膨胀 | 宽度有节律地"呼吸"，一屏可控 |
| 玩家可能"选到一条只有战斗的路" | 汇聚前一段可强制插入休息点 |

## 5. 生成算法

### 5.1 总览

```
Generate(seed, config) →
    A. 行宽序列      （随机 walk + 约束）
    B. 节点坐标      （均分 + 种子抖动）
    C. 连边          （单调匹配，禁交叉）
    D. 反向修补      （补入度、补出度）
    E. 不变量校验    （失败则换种子重试，最多 20 次）
    F. 节点类型分配  （行级允许集 + 全局配额 + 路径校验）
```

**核心原则：这是一个"约束生成"问题，不能生成完再修补。**

### 5.2 A. 行宽序列

```csharp
counts[0] = 1;
counts[rowCount-1] = 1;                       // BOSS 前一行
for (int r = 1; r < rowCount-1; r++) {
    int prev = counts[r-1];
    int pick = WeightedPick(rng, cfg.rowWidthWeights);   // 权重偏向 2、3
    pick = Mathf.Clamp(pick, Mathf.Max(1, prev-1), Mathf.Min(cfg.maxNodesPerRow, prev+1));
    counts[r] = pick;
}
foreach (int r in cfg.convergeRows) counts[r] = 1;       // 强制汇聚
```

**权重建议**（`rowWidthWeights`）：`1 → 0.15`，`2 → 0.35`，`3 → 0.32`，`4 → 0.18`

**为什么要夹 ±1**：从 1 个节点直接跳到 4 个，视觉上是一条线突然炸成扇形，和"手绘一页纸"的气质冲突；±1 变化读起来像墨线自然分叉。

### 5.3 B. 节点坐标

```csharp
// 行内均分 + 抖动，保持手绘的不规则
float cell = mapWidth / Mathf.Max(counts[r], 1);
for (int i = 0; i < counts[r]; i++) {
    float cx = (i + 0.5f) * cell - mapWidth * 0.5f;
    cx += rng.Range(-0.35f, 0.35f) * cell;          // 抖动，但有界
    float cy = -r * cfg.rowSpacing;
    nodes[r][i].pos = new Vector2(cx, cy);
}
```

- 抖动必须**有界**（±35% 格宽），否则会出现节点顺序与索引不一致，导致边交叉
- 抖动必须**按索引单调**：`x[i] < x[i+1]` 永远成立，连边算法依赖这个性质
- 抖动值由种子决定，**不得**使用 `UnityEngine.Random` 全局实例

### 5.4 C. 连边（单调匹配，禁交叉）

这是整个算法最关键的一步。做法：源节点按 x 升序处理，并维护一个 `minTarget` 指针，保证目标的 x 单调不减 —— **数学上就排除了边交叉**。

```csharp
int minTarget = 0;
for (int i = 0; i < counts[r]; i++) {          // 源节点已按 x 升序
    int outDegree = rng.NextDouble() < cfg.twoEdgeChance ? 2 : 1;
    int first = NearestIndexByX(nextRow, nodes[r][i].x);   // 最近的下一层节点
    first = Mathf.Max(first, minTarget);                    // 不许往左回折

    for (int k = 0; k < outDegree; k++) {
        int t = first + k;
        if (t >= counts[r+1]) break;
        AddEdge(nodes[r][i], nodes[r+1][t]);
    }
    minTarget = Mathf.Max(minTarget, first);   // 只允许向右推进
}
```

**为什么要 `minTarget`**：如果允许 A 连到右边、B 连到左边，两条边必然交叉。一旦交叉，手绘线条会糊成一团，观感直接崩。

### 5.5 D. 反向修补

```csharp
// D1. 补入度：下一层中没有任何入边的节点 → 连到最近的上层节点
for (int t = 0; t < counts[r+1]; t++) {
    if (InDegree(r+1, t) == 0) {
        int src = NearestIndexByX(row r, nodes[r+1][t].x);
        AddEdge(nodes[r][src], nodes[r+1][t]);
    }
}

// D2. 补出度：非最后一行、出度为 0 的节点 → 补一条到最近的下层节点
for (int i = 0; i < counts[r]; i++) {
    if (OutDegree(r, i) == 0) {
        int t = NearestIndexByX(row r+1, nodes[r][i].x);
        AddEdge(nodes[r][i], nodes[r+1][t]);
    }
}
```

修补可能引入新的交叉（D1 可能连到左侧），所以**修补后必须重跑一次交叉检测**；若检测失败，进入 E 的重试流程。

### 5.6 E. 不变量校验

```csharp
bool Validate(MapData map) {
    Assert(每行节点数 ∈ [1, maxNodesPerRow]);
    Assert(相邻行宽度差 ≤ 1);
    Assert(汇聚行节点数 == 1);
    Assert(每个非 BOSS 节点 OutDegree ≥ 1);
    Assert(每个非起点节点 InDegree ≥ 1);
    Assert(起点可达所有节点);          // BFS
    Assert(所有节点可达 BOSS);         // 反向 BFS
    Assert(无交叉边);                 // 对每对边做 (a1<a2 && b1>b2) 检测
    Assert(无重复边、无自环);
    return true;
}
```

- 校验失败 → `seed++` 重试，最多 20 次；仍失败则 `throw`（说明配置本身矛盾，应视为程序缺陷而不是运行时容错）
- 校验在 **Editor / Dev 构建**常开，**Release** 关闭以省性能（生成本身只需毫秒级）

### 5.7 复杂度

15 行 × 4 节点 = 最多 60 个节点、约 90 条边。连边是 `O(rows × nodes × outDegree)`，交叉检测是 `O(edges²)` ≈ 8100 次比较。整体 **< 1 ms**，可以在场景加载时同步完成，不需要异步或分帧。

## 6. 节点类型

### 6.1 类型清单

| 类型 | 代码 | 图标 | 进入效果 |
|---|---|---|---|
| 普通战斗 | `Battle` | 交叉双剑 | 进入战斗场景，敌人按行权重抽取 |
| 精英战斗 | `Elite` | 爪痕/头骨 | 高难度战斗，必掉遗物 |
| 事件 | `Event` | 问号（手绘） | 进入事件文本，多选项 |
| 商店 | `Shop` | 钱袋 | 买卡/道具/移除卡 |
| 休息点 | `Rest` | 篝火 | 回血 或 升级卡（二选一） |
| 宝箱 | `Treasure` | 木箱 | 免费获得遗物/道具 |
| BOSS | `Boss` | 头骨（大） | 幕终战 |

### 6.2 行级允许集

| 行 | 允许类型 |
|---|---|
| 0 | `Battle`（固定，教学关） |
| 1 | `Battle`, `Event` |
| 2–3 | `Battle`, `Event`, `Elite` |
| 4 | `Event`, `Shop`, `Rest`, `Battle` |
| 5 | `Battle` |
| 6（汇聚） | `Rest` 或 `Treasure`（二选一固定） |
| 7–8 | `Battle`, `Event`, `Elite` |
| 9 | `Shop`, `Event` |
| 10–11 | `Battle`, `Elite` |
| 12（汇聚） | `Rest`（固定） |
| 13 | `Battle`（BOSS 前最后一战） |

### 6.3 全局配额

| 约束 | 值 |
|---|---|
| 精英总数 | 2–3 |
| 精英不得连续两行 | 是 |
| 商店总数 | ≥ 1 |
| 休息点总数 | ≥ 2 |
| 宝箱 | 0–1 |
| 同类型不得连续 3 行 | 是 |

### 6.4 路径校验（关键）

生成完类型后，枚举所有"起点 → BOSS"路径（数量可控，最多几十条），逐条检查：

```
若某路径上 Rest 数量 == 0 → 在该路径中段随机选一个节点改为 Rest
若某路径上 Shop 数量 == 0 且全局仅 1 个 Shop → 不修改（允许"错过商店"）
若某路径上 Elite 数量 > 2     → 把超出部分降级为 Battle
```

> 这条是玩家体验的底线：**任何一条路都要能"回血"**，否则会出现"选错一次，血线再也救不回来"的恶性体验。

## 7. 表现规范

### 7.1 视觉基调

| 元素 | 规范 |
|---|---|
| 背景 | 羊皮纸纹理，`#E8DCC0` 基调，四角暗角（vignette 25%），纸面有轻微褶皱高光 |
| 页边 | 不规则波浪边（对应草图外框），边缘可见纸张厚度阴影 2px |
| 墨色 | 主线 `#2B2622`（不是纯黑），未访问节点 70% 不透明 |
| 节点 | 手绘圆圈，**3 种变体**随机使用（略扁/略歪/带缺口），直径 72px，描边 3px |
| 边 | 3–5 段贝塞尔，两端渐细（宽 3px → 1.5px），带轻微抖动 |
| 图标 | 手绘线稿风，56×56，居中于节点 |
| 字体 | 手写体（如「霞鹜文楷」/「思源宋体」），标题字号 40，节点标签 20 |

### 7.2 倾斜与视角

**方案 A（推荐，纯 2D）**：平面俯视，靠纸纹 + 墨线 + 相机平移营造"纸地图"感。命中检测简单，无透视畸变。

**方案 B（更接近铭刻）**：地图平面绕 X 轴旋转 25–35°，相机轻微透视。观感更强，但：
- 需要 3D 相机与透视，2D 项目要额外引入
- 节点点击要做好射线拾取
- 极端倾角下下方节点会被遮挡

> 建议先用方案 A 做完，把视觉重心放在"墨线质量 + 纸张质感 + 棋子动画"上，这三项对观感的贡献远大于透视。

### 7.3 线条抖动

手绘感来自"不完美的直线"，但**抖动必须锁定种子**：

```csharp
// 每条边生成一次抖动顶点，缓存起来复用；绝不在 Update 里重算
float seedForEdge = Hash(edge.fromId, edge.toId, mapSeed);
Vector2[] pts = BuildWobblyBezier(a.pos, b.pos, segments: 4, jitter: 2.5f, seed: seedForEdge);
```

若每帧重算，线条会"沸腾"，完全破坏静态手绘感。

### 7.4 动效时长

| 事件 | 时长 | 缓动 |
|---|---|---|
| 地图入场（逐行淡入） | 0.35s/行，行间错开 0.08s | ease-out |
| 节点悬浮 | 0.12s 放大到 1.12 | ease-out |
| 棋子移动到下一节点 | 0.45s | ease-in-out + 中途小跳 8px |
| 落点墨点扩散 | 0.3s | ease-out |
| 未选分支被划掉 | 0.4s 墨迹沿边推进 | linear |
| 揭雾（新行可见） | 0.5s 淡出 | ease-out |
| 节点不可点击抖动 | 0.15s，水平 ±4px | — |

### 7.5 状态视觉

| 状态 | 表现 |
|---|---|
| 可前往 | 描边加粗 1.5 倍，外发光（暖白），轻微呼吸（周期 2s） |
| 当前所在 | 棋子压在上面，节点描边最深，加内阴影 |
| 已访问 | 60% 不透明，加黑色小勾/墨点，去掉发光 |
| 不可达（未选分支） | 墨迹划掉 + 30% 不透明 |
| 未揭示 | 完全被雾/墨覆盖，仅显示模糊轮廓 |
| 不可点击（其他） | 正常显示但无反馈，光标为箭头 |

### 7.6 揭雾规则

- 玩家所在行及**之后 2 行**可见
- 更远的行显示为纸上的淡墨轮廓（不是全黑），保留"目的地可期"的期待感
- BOSS 节点从一开始就以**暗红墨色**显示在纸的最远处

## 8. 交互规范

### 8.1 鼠标

| 操作 | 结果 |
|---|---|
| 悬停可前往节点 | 放大 1.12 + 显示 tooltip（类型名 + 简短描述） |
| 点击可前往节点 | 棋子移动 → 触发节点事件 |
| 点击不可前往节点 | 抖动 + 拒绝音，不移动 |
| 悬停边 | 边加亮 20%，无其他反应 |
| 右键 | 无功能（避免误操作） |
| 滚轮 | 纵向平移地图（当整图高度超出一屏时） |

### 8.2 键盘 / 手柄

| 键 | 功能 |
|---|---|
| `A`/`D` 或 `←`/`→` | 在当前可前往节点间切换焦点 |
| `Enter`/`Space` | 确认前往 |
| `W`/`S` | 平移视野 |
| `Esc` | 暂停菜单 |

### 8.3 移动限制

- **只能前进**，不能回到已访问节点
- 一旦选择，其余同层可选项**立即被划掉**（不可挽回，这是 Roguelike 的代价感）
- 移动过程中输入锁定（0.45s），防止连点
- 事件结算后返回地图，此时才是下一个可操作点

## 9. 数据结构

```csharp
public enum NodeType { Battle, Elite, Event, Shop, Rest, Treasure, Boss }

[Serializable]
public class MapNode {
    public int id;              // 全局唯一，= row * 100 + index
    public int row;
    public int index;
    public NodeType type;
    public Vector2 pos;         // 地图局部坐标
    public List<int> next = new();   // 指向下一行的节点 id
    public List<int> prev = new();
    public bool revealed;       // 是否已揭雾（运行时状态，不入档）
}

[Serializable]
public class MapEdge {
    public int from;
    public int to;
    public Vector2[] bezierPts;  // 生成时缓存，含种子抖动
    public bool crossedOut;      // 未选分支被划掉
}

[Serializable]
public class MapData {
    public int seed;
    public int rowCount;
    public List<MapNode> nodes = new();
    public List<MapEdge> edges = new();
    public List<int>[] rows;      // 每行的节点 id 列表
}

[Serializable]
public class MapState {           // 存档内容
    public int seed;
    public List<int> visitedPath; // 已访问的节点 id 序列
    public int currentIndex;      // visitedPath 的最后一项
}
```

**`MapConfig`（ScriptableObject）**：`rowCount`、`maxNodesPerRow`、`convergeRows[]`、`rowWidthWeights[]`、`twoEdgeChance`、`rowSpacing`、`mapWidth`、`typeWeightsPerRow[]`、`globalQuotas`。

## 10. 存档与确定性

### 10.1 存档只存种子

| 方案 | 存档体积 | 优点 | 缺点 |
|---|---|---|---|
| 存完整 `MapData` | 数十 KB | 实现简单 | 版本更新后旧档结构不兼容 |
| **存 `seed` + `visitedPath`** | 数百字节 | 极小、天然向前兼容、可重放 | 生成算法一旦改动，旧档会变成另一张图 |

**结论：存种子。** 代价是"生成算法不能随意改"，需要用 `mapGeneratorVersion` 字段把旧档绑定到旧版本（详见 10.3）。

### 10.2 恢复流程

```
Load(MapState state)
  → var data = MapGenerator.Generate(state.seed, config, version: state.generatorVersion)
  → foreach (id in state.visitedPath) MarkVisited(id)
  → 把 currentIndex 之前的同层兄弟节点标记为 crossedOut
  → 相机定位到当前节点
```

### 10.3 版本兼容

`MapState` 增加 `generatorVersion` 字段。算法改动时递增版本号，旧档用旧版本的生成逻辑（保留旧版本代码路径）或直接提示"该档地图不再兼容"。

## 11. Unity 技术方案

### 11.1 模块划分

| 模块 | 类型 | 职责 | 依赖 |
|---|---|---|---|
| `MapConfig` | ScriptableObject | 全部可调参数 | — |
| `MapGenerator` | 纯 C# 静态类 | 生成 + 校验 | `MapConfig` |
| `MapValidator` | 纯 C# 静态类 | 不变量断言 | `MapData` |
| `MapData` / `MapNode` / `MapEdge` | POCO | 数据载体，可 JSON | — |
| `MapView` | MonoBehaviour | 渲染节点、边、雾 | `MapData` |
| `NodeView` | MonoBehaviour | 单节点渲染与状态 | — |
| `EdgeRenderer` | MonoBehaviour | 贝塞尔网格生成 | — |
| `MapInput` | MonoBehaviour | 点击/悬停/键鼠 | `MapNavigation` |
| `MapNavigation` | MonoBehaviour | 推进、锁定、事件派发 | `MapData`, `MapState` |
| `MapCamera` | MonoBehaviour | 平移、边界、揭雾触发 | — |
| `MapSaveService` | 静态服务 | 序列化 `MapState` | — |

**关键：`MapGenerator` 与 `MapValidator` 不引用 UnityEngine 的随机与 Time，只依赖 `MapConfig` 的纯数据 + 传入的 `System.Random`。** 这样才能在 EditMode 测试里跑几千次生成，验证不变量。

### 11.2 边的渲染选型

| 方案 | 适用 | 评价 |
|---|---|---|
| `LineRenderer`（每边一个） | 边数 < 50 | 简单，但每边一个组件、材质合批差 |
| **单个 Mesh（推荐）** | 任意 | 所有边合并成 1 个 Mesh，1 个 DrawCall；支持自定义渐细宽度 |
| `UILineRenderer`（UGUI） | UI 层实现 | 与 Canvas 合批，但控制力弱 |
| Sprite 拼接 | 直线边 | 无法做抖动手绘，排除 |

**推荐单 Mesh**：把每条边的贝塞尔采样成三角带（每段 2 个顶点，宽度沿 t 从 3px 渐变到 1.5px），全部塞进一个 Mesh，1 次 DrawCall 画完 90 条边。

### 11.3 节点渲染

- `NodeView` 用对象池，预生成 `maxNodesPerRow × rowCount = 60` 个
- 每个节点 = 1 个 `SpriteRenderer`（手绘圆，3 变体）+ 1 个图标 `SpriteRenderer` + 1 个状态叠加层
- 图标用图集（2048×2048 足够放全部类型），同图集可合批

### 11.4 性能预算

| 指标 | 目标 |
|---|---|
| 地图场景 DrawCall | ≤ 10（背景 1 + 边 1 + 节点图集 2 + 图标 2 + 雾 1 + UI 3） |
| 生成耗时 | < 1 ms |
| 进场动画总时长 | < 1.5 s |
| 内存 | < 30 MB（含图集） |

## 附录 A：生成伪代码（完整版）

```
function Generate(seed, cfg):
    rng = System.Random(seed)
    map = new MapData(seed)

    # A. 行宽
    counts[0] = 1
    counts[cfg.rowCount-1] = 1
    for r in 1 .. cfg.rowCount-2:
        pick = WeightedPick(rng, cfg.rowWidthWeights)
        counts[r] = clamp(pick, max(1, counts[r-1]-1), min(cfg.maxNodesPerRow, counts[r-1]+1))
    for r in cfg.convergeRows: counts[r] = 1

    # B. 坐标
    for r in 0 .. cfg.rowCount-1:
        cell = cfg.mapWidth / counts[r]
        for i in 0 .. counts[r]-1:
            x = (i + 0.5) * cell - cfg.mapWidth/2 + rng.Range(-0.35, 0.35) * cell
            y = -r * cfg.rowSpacing
            map.AddNode(r, i, x, y)

    # C. 连边（单调匹配）
    for r in 0 .. cfg.rowCount-2:
        minTarget = 0
        for i in 0 .. counts[r]-1:
            degree = (rng.NextDouble() < cfg.twoEdgeChance) ? 2 : 1
            first = max(NearestByX(counts[r+1], node.x), minTarget)
            for k in 0 .. degree-1:
                t = first + k
                if t < counts[r+1]: map.AddEdge(node(r,i), node(r+1,t))
            minTarget = max(minTarget, first)

    # D. 修补
    RepairInDegree(map)                    # 下层孤儿
    RepairOutDegree(map)                   # 上层死路

    # E. 校验
    if not Validate(map): return Generate(seed+1, cfg)   # 最多 20 次

    # F. 类型
    for r in 0 .. cfg.rowCount-1:
        for each node in row r:
            node.type = PickType(rng, cfg.allowedTypes[r], cfg.globalQuotas, map.currentTypeCount)
    EnforcePathConstraints(map, cfg)        # 每条路径至少 1 个 Rest

    return map
```

## 附录 B：参考与差异说明

本方案借鉴了《杀戮尖塔》的"分层 DAG + 约束生成 + 不变量校验"思路，但把拓扑从"宽 DAG 不要求合流"改为"带状 + 强制汇聚"，以匹配《邪恶铭刻》的单线朝圣感与手绘纸面观感。`MapGenerator` 的实现不依赖任何第三方地图库，全部逻辑自研。
